# New cards: input validity, bounded reads, retention, loud shims

Quotes were read from the live pages with `curl -sL` on 2026-11-01 and stripped of markup. Orgs follow `tools/orgs.py`.

## svc-invalid-input-is-4xx (stable)

Clause A: check the value against its domain (range, set, existence, encoding) at the boundary and reject. Clause B: the failure is a 4xx, never a 5xx.

- OWASP, https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html. "Numbers and dates Expected type, accepted format, and minimum and maximum values". "Agree on a character encoding across components and reject malformed input." "Reject invalid requests with a clear error; do not continue with partially validated data." Backs A.
- Google, https://grpc.io/docs/guides/status-codes/. "INVALID_ARGUMENT 3 The client specified an invalid argument." and "The following status codes are never generated by the library, only by user code: INVALID_ARGUMENT NOT_FOUND". Backs A and B (googleapis code.proto maps INVALID_ARGUMENT to "HTTP Mapping: 400 Bad Request"). NOT_FOUND: "Some requested entity (e.g., file or directory) was not found."
- Kubernetes, https://github.com/kubernetes/community/blob/master/contributors/devel/sig-architecture/api-conventions.md. "`422 StatusUnprocessableEntity` * Indicates that the requested create or update operation cannot be completed due to invalid data provided as part of the request. * Suggested client recovery behavior: * Do not retry. Fix the request." and "`404 StatusNotFound` * Indicates that the requested resource does not exist." Backs A, B and the missing id.
- IETF, https://www.rfc-editor.org/rfc/rfc9110.html#name-client-error-4xx. "The 4xx (Client Error) class of status code indicates that the client seems to have erred." "The 5xx (Server Error) class of status code indicates that the server is aware that it has erred or is incapable of performing the requested method." 404: "the origin server did not find a current representation for the target resource". Backs B.
- Microsoft, https://learn.microsoft.com/en-us/azure/architecture/best-practices/api-design. "400 (Bad Request) The client has placed invalid data in the request." Backs B.
- Stripe, https://docs.stripe.com/api/errors. "400 Bad Request The request was unacceptable, often due to missing a required parameter." Backs B (weak: says nothing about a 5xx or an id).

Orgs per clause: A has OWASP, Google, Kubernetes. B has IETF, Microsoft, Google, Kubernetes, Stripe. Missing id answering 404: IETF, Google, Kubernetes. Weak: Stripe.

Overlap check: svc-bound-client-controlled-sizes covers size and count only. svc-api-specific-status-codes (draft) covers which code fits and the success path. mod-validate-at-boundary-once (draft) is about where the check sits. sys-constraint-not-valid is about adding DB constraints in a migration. None states "invalid input must not reach a 5xx". Kept as distinct.

## fn-bounded-read-fails-at-cap (stable)

Clause: at the cap return an error rather than the prefix.

- Google, https://pkg.go.dev/net/http#MaxBytesReader. "In contrast to io.LimitReader, MaxBytesReader's result is a ReadCloser, returns a non-nil error of type *MaxBytesError for a Read beyond the limit".
- Google, https://pkg.go.dev/io#LimitReader. "LimitReader returns a Reader that reads from r but stops with EOF after n bytes." Same org as above; counts once. Shows the failure mode.
- Django, https://docs.djangoproject.com/en/5.2/ref/settings/#data-upload-max-memory-size. "The maximum size in bytes that a request body may be before a SuspiciousOperation ( RequestDataTooBig ) is raised."
- IETF, https://www.rfc-editor.org/rfc/rfc9110.html#name-413-content-too-large. "The 413 (Content Too Large) status code indicates that the server is refusing to process a request because the request content is larger than the server is willing or able to process."
- OWASP, https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html. "Reject invalid requests with a clear error; do not continue with partially validated data." and "Apply request size limits before buffering or parsing input".

Orgs: Google, Django, IETF, OWASP (four). Weak: IETF and Django speak of request bodies, not files or responses; the card's applies_when says "file, response or request body". OWASP's line is general. Overlap: svc-bound-client-controlled-sizes asks for a cap and is silent on what happens at the cap; fn-fetch-only-needed-data is about queries. Distinct.

## sys-append-only-stores-have-retention (stable)

Clause: a store that only grows gets a maximum age or count, enforced.

- Kubernetes, https://kubernetes.io/docs/concepts/workloads/controllers/ttlafterfinished/. "TTL-after-finished controller assumes that a Job is eligible to be cleaned up TTL seconds after the Job has finished."
- Kubernetes, https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/ (same org). ".spec.successfulJobsHistoryLimit and .spec.failedJobsHistoryLimit fields specify how many completed and failed Jobs should be kept."
- Prometheus, https://prometheus.io/docs/prometheus/latest/storage/. "--storage.tsdb.retention.time : How long to retain samples in storage. If neither this flag nor storage.tsdb.retention.size is set, the retention time defaults to 15d."
- Docker, https://docs.docker.com/engine/logging/drivers/json-file/. "sets the max-size and max-file options to enable automatic log-rotation." Docker is a new org row.
- Elastic, https://www.elastic.co/guide/en/elasticsearch/reference/current/index-lifecycle-management.html. "Rollover : Creates a new write index when the current one reaches a certain size, number of docs, or age." (the page lists lifecycle actions; delete is a later phase, not quoted).
- PostgreSQL, https://www.postgresql.org/docs/current/ddl-partitioning.html. "Dropping an individual partition using DROP TABLE , or doing ALTER TABLE DETACH PARTITION , is far faster than a bulk operation."
- Read but not cited: AWS CloudWatch Logs ("Never Expire" is a retention setting), OWASP Logging ("must not be kept beyond this time", about legal retention).

Orgs: Kubernetes, Prometheus, Docker, Elastic (four) for the age/count rule. PostgreSQL backs only the "drop a partition" sentence in Why. Weak: Elastic's quote shows rollover, not deletion. In-memory maps are covered by Kubernetes history limits by analogy only; no source is about a process-local registry.

Overlap: sys-cache-bounds-invalidation (caches), sys-pii-minimise-retention (personal data only), sys-load-shedding-bounded-queues (queues). A finished-job registry or event table is neither. Kept.

## mod-shim-fails-loudly (draft: evidence)

- PSF, https://docs.python.org/3/library/exceptions.html#NotImplementedError. "abstract methods should raise this exception when they require derived classes to override the method, or while the class is being developed to indicate that the real implementation still needs to be added."
- Rust project, https://doc.rust-lang.org/std/macro.unimplemented.html. "Indicates unimplemented code by panicking with a message of 'not implemented'."
- Oracle, https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/UnsupportedOperationException.html. "Thrown to indicate that the requested operation is not supported."
- Microsoft, https://learn.microsoft.com/en-us/dotnet/api/system.notsupportedexception. "The exception that is thrown when an invoked method is not supported".

Four orgs, but each is an API definition, not a statement of practice about shims or production patches; no source on "no mock or monkeypatch in production". Draft, lacks evidence.
