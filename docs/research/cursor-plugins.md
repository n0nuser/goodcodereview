# Cursor plugins: code-quality and review guidance

Fetched 2026-10-24 through the GitHub API (raw file text, read in full). Source: https://github.com/cursor/plugins. The repo root has no licence file, but each plugin folder read here (`pstack`, `cursor-team-kit`, `dyl-stack`, `thermos`, `agent-compatibility`, `cli-for-agent` and others) carries its own MIT `LICENSE`. This pass still paraphrases only, so no source text is stored here. All files are opinion from one vendor's engineers: no data, no external citations inside the skills. A rule that only this source backs stays `draft` until a second source is found.

Each row gives the URL, the distilled point, whether a reviewer can mark it FAIL from a diff or a tree, and where it lands: an existing card id, a proposed new id (level prefix kept), `glossary`, or `dropped` with the reason.

Read and skipped. Skipped as unrelated to code quality: `grok-voice`, `docs-canvas`, `cursor-sdk`, `origin-apps`, `teaching`, `create-plugin`, `harness/pstack/claude-code` (a copy of pstack), `third_party/`, and the pstack skills for prompts, video, bots and setup. The `thermos` skills were already mapped in `docs/research/second-pass.md` section 1. They were re-read against that file and nothing is missing. The same text also appears in `cursor-team-kit` and in the `interrogate` reference `code-quality-review.md`.

## 1. pstack principles

Base path `https://github.com/cursor/plugins/blob/main/pstack/skills/`.

1. `principle-fix-root-causes/SKILL.md`. Fix the first wrong decision, not the place the wrong state showed up. Guards, retries, swallowed errors, clamped values and discarded state are the usual ways to hide a bug. A workaround that needs a paragraph of comment means the code is wrong. Search for every other instance of the same fault. FAIL: yes, when the diff adds one of those hides with no stated cause. -> new `chg-fix-root-cause-not-symptom`.
2. `principle-fix-root-causes/SKILL.md`, rule on restarts. A bug that appears only after a restart points at persisted state (config, cache, lock file, serialised state). Debugging hint. -> dropped: investigation tip, nothing to FAIL.
3. `principle-attack-the-premise/SKILL.md`. After two failed fixes that share one assumption, write the assumption down and test it before the third fix. -> dropped: author process, not visible in a diff.
4. `principle-boundary-discipline/SKILL.md`. Validate and narrow types where data enters. Inside, trust the types and skip repeat nil checks. Business logic sits in pure functions and the framework shell stays thin. FAIL: yes. -> `mod-validate-at-boundary-once`, `mod-thin-entry-point`.
5. `principle-boundary-discipline/SKILL.md`, rule on the public surface. Do not re-export transport, storage, framework or wire types. Expose domain concepts. FAIL: yes. -> new `mod-no-wire-types-in-public-api`.
6. `principle-type-system-discipline/SKILL.md`. Give semantic primitives their own types (`UserId` is not `OrderId`), validated once at creation. Two arguments of one primitive type with different meanings need distinct types. FAIL: yes. -> new `fn-distinct-types-for-ids`.
7. `principle-type-system-discipline/SKILL.md`. Where a schema, protobuf, OpenAPI file or migration owns a shape, derive the type from it instead of hand-writing a parallel one. FAIL: yes. -> new `mod-derive-dont-duplicate`.
8. `principle-type-system-discipline/SKILL.md`. External data (RPC, JSON, env vars, CLI args, DB rows) is untyped until a parse function at the boundary turns it into the model. FAIL: yes. -> `mod-validate-at-boundary-once`.
9. `principle-model-the-domain/SKILL.md`. Use a state machine, tagged union, table or typed model in place of scattered booleans and growing if/else chains. A second boolean that must stay in sync with the first is the tell. FAIL: yes. -> new `fn-variants-as-tagged-union`; the growing-chain half supports `chg-no-special-case-branches`.
10. `principle-model-the-domain/SKILL.md`. Organise a module around one body of domain knowledge, not around load, validate, transform and save in order. FAIL: judgement call. -> `mod-cohesive-unit`.
11. `principle-model-the-domain/SKILL.md`. Keep boring code when the shape is already clear. An abstraction that removes no branch, duplicate rule or invalid state is suspect. -> `mod-no-wrong-abstraction`.
12. `principle-foundational-thinking/SKILL.md`. Data shape before logic. Remove duplication in structure, not in every line, and three similar statements beat a premature abstraction. Ask what happens if another actor changes shared state at the same moment. -> `chg-abstraction-needs-two-callers`, `mod-no-wrong-abstraction`; the shared-state question -> row 22.
13. `principle-foundational-thinking/SKILL.md`. Scaffold first (CI, lint, test setup, shared types), commits small and single-purpose. -> `chg-one-concern`, `code-ci-gates`.
14. `principle-minimize-reader-load/SKILL.md`. Maintainability is the work a reader does: layers to trace and state to hold. The two are independent. Inline one-caller wrappers and adapters with no second implementation. Shrink state scope (return values over mutation, locals over fields over module state over globals). -> `fn-no-pass-through-wrapper`, `mod-no-module-mutable-state`, `mod-deep-modules`.
15. `principle-minimize-reader-load/SKILL.md`, 30-second test: can a new reader say where X comes from and what can change it? FAIL: judgement. -> glossary: reader load (two axes). No entry written.
16. `principle-laziness-protocol/SKILL.md`. Put a decision behind one source of truth and pass a flag. Prefer the smallest diff. FAIL: yes for the first half. -> `mod-central-config`, `chg-one-concern`.
17. `principle-subtract-before-you-add/SKILL.md`. Remove complexity first. No speculative validators or guards beyond the spec. Delete a reference with no novel content instead of leaving a stub. FAIL: yes. -> `mod-yagni`.
18. `principle-make-operations-idempotent/SKILL.md`. Every state-changing operation must converge when run twice or after a crash at any point. Derive each step from current state. Leftovers (locks, temp files, half-written records, claimed jobs) must be recognisable as stale by the next run. Write to a temp path and rename. FAIL: yes. -> new `fn-rerun-safe-after-crash`; the API-key half is `svc-idempotency-key`.
19. `principle-separate-before-serializing-shared-state/SKILL.md`. First ask whether the actors need the same mutable object. Give each its own file, key or branch and merge at read time. If sharing is real, enforce serialisation structurally (lock, single writer, compare-and-swap). A convention is not concurrency control. Two workers writing their own field into one state file still share it. FAIL: yes. -> new `mod-single-writer-per-state`.
20. `principle-migrate-callers-then-delete-legacy-apis/SKILL.md`. With no external consumers, move every caller to the new API and delete the old one in the same change, and delete tests that only pinned the old internals. FAIL: yes, and it pulls the opposite way to `chg-expand-contract`, which applies when consumers exist outside the repo. -> new `chg-delete-legacy-after-migration`, with `applies_when` set to "no consumers outside the repo".
21. `principle-outcome-oriented-execution/SKILL.md`. In a planned rewrite, accept scoped, reversible breakage between phases and prove the end state. -> dropped: planning posture, and it conflicts with per-commit green in `chg-one-concern`.
22. `principle-prove-it-works/SKILL.md`. Check the real thing, not a proxy (file mtime, cached screenshot, self-report, "it compiles"). If a check fails, suspect the observation method first. Prefer a re-runnable script as the artifact. FAIL: yes for claims in a PR. -> `chg-verify-before-claim`, `chg-agent-independent-review`.
23. `principle-test-behavior-not-implementation/SKILL.md`. Judge a test by two edits: break the behaviour (the test must fail) and refactor the internals (the test must pass). Expected values come from the requirement, not from running the code. FAIL: yes. -> `chg-agent-mock-asserting-tests`, `mod-mock-at-boundaries-only`, `py-no-init-or-model-tests`.
24. `principle-test-behavior-not-implementation/SKILL.md`. Pair a "was not called" assertion with a case where the call happens, or the test cannot see the call. Assert the error type callers branch on, not its wording. Data the test built itself proves nothing. FAIL: yes. -> new `fn-test-oracle-independent`.
25. `principle-explain-the-number/SKILL.md`. A performance or eval number needs a run count, a spread and a named limiter (the resource that stops it being twice as good). List what else the number could measure (errors, cached or skipped work, an untuned side, noise, a piece too small to matter). FAIL: yes for a PR that claims a speed-up. -> new `chg-perf-claim-evidence`.
26. `principle-sequence-verifiable-units/SKILL.md`. Verify each unit before the next; in a sweep, bracket every change with a check. Deliver the failing test first, then the fix. -> `chg-tests-ship-with-change`; the commit order half is dropped: history shape is not visible in a diff.
27. `principle-redesign-from-first-principles/SKILL.md`. Do not bolt a change onto the old design. Redesign as if the requirement had always existed, then update types, docs and examples together. -> dropped: posture. The visible symptom (a patch grown onto an existing chain) is `chg-no-special-case-branches`.
28. `principle-encode-lessons-in-structure/SKILL.md`. If a recurring instruction can be enforced, use the structural fix (type, lint, check) and drop the instruction. -> new `code-rule-has-enforcer` (with row 33).
29. `principle-build-the-lever/SKILL.md`. For non-trivial work, write the codemod or script, so a reviewer can read and re-run it. The script can be rerun to check the work. -> dropped: author workflow, not failable from the diff.
30. Remaining principles: `principle-exhaust-the-design-space`, `principle-experience-first`, `principle-guard-the-context-window`, `principle-never-block-on-the-human`. -> dropped: design-process posture, product taste and agent-runtime rules.

## 2. pstack skills

31. `correct/SKILL.md`. Group repeated corrections into classes (a class counts after two cases). Fix each at the highest level that works: architecture, then types, then a lint or CI check whose message names the function to use, then tests, with prose rules last. Prove the check fails on a real past mistake. A rule that already existed but is not enforced is a repeat. FAIL: yes at the codebase level. -> new `code-rule-has-enforcer`.
32. `correct/SKILL.md`. For a pattern that is already common, fail only when a change adds more of it. Exceptions carry a reason, an expiry date and an approver. FAIL: yes. -> `code-ci-gates`; the expiry detail supports `chg-no-silenced-diagnostics`.
33. `no-comments/SKILL.md`. A comment survives only for a legal header, behaviour forced by a vendor or protocol we cannot change, a public API contract, or a link that explains a constraint code cannot express. A surprise in our own code gets a rename, type or restructure. FAIL: yes. -> `fn-comments-explain-why`, `fn-comments-survive-context`.
34. `no-comments/SKILL.md`. Comments saying "do not remove", "important" or a long justification are signals to investigate, not proof. A constraint comment should become a type, a lint or a test, then be deleted. Suppressions of rules that guard correctness or safety are removed. FAIL: yes. -> `chg-no-silenced-diagnostics`, new `code-rule-has-enforcer`.
35. `blast-radius/SKILL.md`. Listing callers is not the job. Look where grep stops: JSON an API returns, a DB column, a wire format read by another language, a feature flag, code three hops away, the library's pinned source. FAIL: yes when a change touches such a surface and the PR names none. -> `chg-breaking-change-taxonomy`.
36. `blast-radius/SKILL.md`. Find the one fact the change is safe because of and prove it by running code. Rank evidence: asserted, pointed at a line, walked through, run, reproduced. Mark an unproven fact as unproven. FAIL: yes. -> `chg-verify-before-claim`.
37. `tdd/SKILL.md`. For a bug fix, write the smallest failing test, run it and confirm it fails for the intended reason, then fix. Never edit a test to match a wrong implementation or weaken an assertion without a reason. Prefer no new test to a bad one (mock-only, implementation-bound, timing-dependent). FAIL: yes. -> `chg-tests-ship-with-change`, `chg-agent-mock-asserting-tests`, `chg-verify-before-claim`.
38. `typescript-best-practices/SKILL.md`. Tagged unions over optional-field bags, a `never` check in the default arm so a new variant fails the build, `unknown` over `any`, no `as` casts, type guards that actually verify (a lying guard hides a bug behind a safe-sounding name), `satisfies` over `as`, and build the type from legal parts (a non-empty tuple) instead of a runtime length check. FAIL: yes, language-specific. -> `py-no-cast` for the cast and guard rules, `fn-variants-as-tagged-union` for unions and exhaustiveness.
39. `typescript-best-practices/SKILL.md`. Pass objects, not positional arguments, except on hot paths. -> `fn-bool-arg-at-callsite` (positional-argument readability).
40. `typescript-best-practices/SKILL.md`. Do not mock what you can run. No `console.log` in shipped code. -> `mod-mock-at-boundaries-only`; the logging rule is dropped: a linter owns it.
41. `architect/references/design-red-flags.md`. Shallow module: callers need several calls for one operation, options expose internal stages. -> `mod-deep-modules`.
42. `architect/references/design-red-flags.md`. Information leakage: the same decision (a representation, policy or protocol detail) lives in two modules, so a change needs coordinated edits. -> `mod-fowler-smells` (Shotgun Surgery) and row 5.
43. `architect/references/design-red-flags.md`. Temporal decomposition: modules split by execution order repeat one representation and its invariants. -> `mod-cohesive-unit`.
44. `architect/references/design-red-flags.md`. Pass-through method that forwards the same arguments to the same shape. -> `fn-no-pass-through-wrapper`.
45. `architect/references/design-red-flags.md`. Split ownership: more than one module writes or copies the same state. -> new `mod-single-writer-per-state`.
46. `architect/references/design-red-flags.md`. Two supported ways to do one task, so both keep gaining callers. Keep one and delete the others in the same change. -> new `chg-delete-legacy-after-migration`; the standing-pattern audit is `code-consistency-drift`.
47. `architect/references/design-red-flags.md`. Importable internals: a caller can reach a module's internals, so they become the interface. Make the import fail the build. FAIL: yes. -> new `mod-internals-unreachable`.
48. `architect/references/design-red-flags.md`. Hand-synced list: two places enumerate the same items. Derive one from the other or fail the build when they disagree. FAIL: yes. -> new `mod-derive-dont-duplicate`.
49. `architect/SKILL.md`, "Scrap" tells. Signs the shape is wrong: the same workaround repeating in unrelated code, many edge cases each with a special branch, types that need `any`, casts or always-set optionals, callers who must know the abstraction's internal rules. -> `chg-no-special-case-branches`, `mod-deep-modules`.
50. `architect/SKILL.md`, design twice and write the caller's usage first. -> dropped: design process, not visible in a diff.
51. `interrogate/references/rubric.md`. Root cause versus symptom: a guard that masks a broken invariant, a retry that hides a broken contract, a cast that silences a modelling error. Ask what the proper fix would be. FAIL: yes. -> new `chg-fix-root-cause-not-symptom`.
52. `interrogate/references/rubric.md`. A "don't do X" comment or convention should be a type, lint or runtime check when it can. -> new `code-rule-has-enforcer`.
53. `interrogate/references/rubric.md`. Legacy dual-paths: a new API while the old one stays, with no external consumer, is debt. -> new `chg-delete-legacy-after-migration`.
54. `interrogate/references/rubric.md`. Trace the execution path for a claimed bug and trace an input to a dangerous sink for a security claim. Do not flag "could be nil" without the call chain that makes it nil. -> `chg-verify-before-claim`.
55. `interrogate/references/lead-judgment.md`. Reviewers inflate nits to fill a review. Drop hypotheticals the call site cannot reach, "I would do it differently" with no concrete problem, and findings about code the author did not touch. Two independent models raising the same issue is the strongest signal. Be most careful with security and correctness findings from a single model. The reviewer prompt tells reviewers to say "no findings" when there are none, to skip praise, and to separate "broken" from "I would do it differently", with severities critical, warning and nit. -> `chg-review-signal`, `chg-agent-independent-review`.
56. `interrogate/SKILL.md`. State the change's intent in one paragraph before reviewing. Sort findings into act on, consider, noted, dismissed, each with a reason. -> `chg-matches-spec` for the intent; the buckets map to `chg-review-comment-format` severities (block, should-fix, nit).
57. `bug-fix` playbook, `poteto-mode/playbooks/bug-fix.md`. Every shipped line traces to runtime evidence. A "might help" guard is a hypothesis and does not ship. Reproduce first, verify on the same surface, and land the failing repro before the fix. FAIL: yes. -> `chg-fix-root-cause-not-symptom`, `chg-verify-before-claim`.
58. `refactoring` playbook, `poteto-mode/playbooks/refactoring.md`. Pin current behaviour with a characterization test, snapshot or equivalence harness before moving structure. Type check and lint are not a pin. FAIL: yes for a refactor PR. -> new `chg-refactor-has-behaviour-pin`.
59. `refactoring` playbook. For an API reshape, migrate every caller and delete the old API in the same wave, with no compatibility shim. Spot-check renames, because they miss strings, prose and back-references. -> new `chg-delete-legacy-after-migration`; the rename check is dropped: it is a manual step.
60. `refactoring` playbook. A refactor is worth keeping only if it lowers reader load somewhere. Otherwise revert. Subtraction commit, then reshape, then cleanup. -> `chg-refactor-separate` and row 14.
61. `perf-issue` playbook, `poteto-mode/playbooks/perf-issue.md`. Tie every fix to a measurement. Try the cheap options in order: do not do it, do not repeat it, do it less, later, concurrently, then cheaper. -> `chg-perf-claim-evidence`; the order is glossary: performance mantras, no entry written.
62. `benchmark-checklist/SKILL.md`. Seven questions for a performance claim: why not double, was each side tuned, did it break a hardware limit (a piece that is 10% of the run caps the gain near 11%), did it error, does it reproduce (at least five alternating runs, median and range), does it matter end to end, did the work run inside the timed region. FAIL: yes. -> new `chg-perf-claim-evidence`.
63. `verify-this/SKILL.md` is a cursor-team-kit skill, not a pstack one. -> dropped: duplicate, see row 77.
64. `opening-a-pr` playbook, `poteto-mode/playbooks/opening-a-pr.md`. A PR body is a one-minute briefing: why, what changed, scope with what is left out, rejected alternatives, blast radius, and how it was proven. Perf claims carry one primary number. Prefer several narrow PRs to one large PR. -> `chg-author-hygiene`, `chg-size-ceiling`.
65. `shipping` playbook, `poteto-mode/playbooks/shipping.md`. A verification verdict covers one patch. After a rebase the SHA changes, so compare the patch id before trusting an older verdict. FAIL: yes, branch-protection style. -> new `chg-approval-tied-to-patch`.
66. `poteto-mode/references/bugbot-triage.md`. Sort bot findings into fix (plausible correctness, security, privacy, data loss, auth, billing, migration, idempotency or race), dismiss (documented noisy pattern, with a reason), ask. When unsure, ask, because skipping a style comment is cheap and skipping a data bug is not. Do not dismiss accessibility findings on the grounds that a visual change was intended. -> `chg-review-signal`.
67. `show-me-your-work/SKILL.md`. Append-only decision log with evidence pointers, an audit against the transcript, and a review of the trail by a model from another family. -> dropped: agent audit trail. The cross-model idea is `chg-agent-independent-review`.
68. `figure-it-out/SKILL.md`. Write the definition of done as a falsifiable predicate, build the verification harness and baseline before the work, and treat inconclusive as not a pass. -> `chg-verify-before-claim`.
69. `unslop/SKILL.md`, `technical-writing/SKILL.md`. Prose rules for AI patterns, plain words and Diátaxis. -> dropped: prose style, already followed by this repo's own writing rules.
70. `reproduce-and-fix-issues` (automations/benny). No confirmed repro means no authored fix. The symptom must appear twice through real UI use, and state inspection may confirm but never force it. If a fix or PR already exists, verify it instead of writing another. -> `chg-verify-before-claim`; the Slack and credential rules are dropped: bot-specific safety.
71. `why/SKILL.md` and `why/references/sources/`. Before judging code, trace its history: blame, the PR that added it, tickets, postmortems. Defensive code (null checks, retries, timeouts, flags) usually answers a real incident. -> `chg-chestertons-fence`.
72. `sharpen`, `in-your-own-words`, `poteto-help`, `how`, `recall`. Prompting and exploration helpers. -> dropped: not code review.

## 3. cursor-team-kit

Base path `https://github.com/cursor/plugins/blob/main/cursor-team-kit/skills/`.

73. `deslop/SKILL.md`. Remove what an AI added that clashes with the file: extra comments, defensive checks or try/catch unusual for trusted paths, `any` casts used to dodge a type error, deep nesting where early returns work. FAIL: yes where the surrounding code shows the local style. -> `chg-agent-grounded-code`, `chg-match-codebase-pattern`, `py-no-cast`, `mod-validate-at-boundary-once`.
74. `make-pr-easy-to-review/SKILL.md`. Reviewability issues: noisy commits, a stale description, unrelated changes, mechanical and logic changes mixed, missing tests, no entry point for the reviewer. The description opens with a summary that matches the real diff, separates core files from generated ones, and names risky changes, migration order and rollout. Never hide a behaviour change in a "cleanup". If the PR is too big for notes to fix, split it. FAIL: yes. -> `chg-author-hygiene`, `chg-refactor-separate`, `chg-size-ceiling`.
75. `make-pr-easy-to-review/SKILL.md`. After a history rewrite, compare the tree hash before and after, and do not push if it changed. -> dropped: author workflow.
76. `review-and-ship/SKILL.md`. Review order: correctness, security, regressions, then style. Findings grouped as critical, warning, note. Judge PR readiness from all attached checks (`gh pr checks`), not only Actions runs. Fix failing hooks instead of bypassing them. -> `chg-review-signal`, `chg-review-comment-format`; check state is `code-ci-gates`; hook bypass is dropped: not visible in a diff.
77. `verify-this/SKILL.md`. Restate the claim as a condition, metric and threshold. Capture a baseline from the old state and a treatment with the same command, data and environment. Return one verdict: verified, not verified or inconclusive, and do not soften a negative. Vague claims such as "cleaner" are not verifiable. FAIL: yes for a measurable claim. -> `chg-verify-before-claim`, `chg-perf-claim-evidence`.
78. `fix-ci/SKILL.md`, `loop-on-ci/SKILL.md`. Fix one failure cause at a time. Retry a flaky test once and report evidence. If a failure is unrelated and already fixed on main, merge main instead of widening the PR. -> dropped: CI workflow. The unrelated-fix part is `chg-one-concern`.
79. `check-compiler-errors`, `get-pr-comments`, `new-branch-and-pr`, `fix-merge-conflicts`, `run-smoke-tests`, `weekly-review`, `what-did-i-get-done`, `workflow-from-chats`, `control-cli`, `control-ui`. Task runners and agent mechanics. -> dropped: no review rule.
80. `pr-review-canvas/SKILL.md` (also the standalone plugin). Present a diff to the reviewer in this order: core logic, wiring, mechanical files summarised. Add pseudocode only for dense logic, trace one concrete input through old and new code for surprising behaviour changes, and tag a risky hunk. Overused callouts destroy signal. -> dropped: presentation tool. The overuse point is `chg-review-signal`.

## 4. dyl-stack

Base path `https://github.com/cursor/plugins/blob/main/dyl-stack/skills/`.

81. `dyl-mode/SKILL.md`, root-cause gate. Before a fix, write "cause X because mechanism Y", where Y is something seen in runtime output or a compiler error, not the symptom restated. These mark a symptom fix until that line justifies them: a null guard where a crash was, a swallowing try/catch, `as any`, `!`, `ts-ignore` or `eslint-disable`, a retry, sleep or longer timeout, `.skip`, a weakened assertion or snapshot update, a special case for the failing input, a hard-coded value. FAIL: yes. This is the most checkable list in the repo. -> new `chg-fix-root-cause-not-symptom`.
82. `dyl-mode/SKILL.md`. "Merge-ready" is a list that must hold on the current head. Latest review green, not draft, no conflicts, every check ran and passed (required or not), every thread resolved. -> `chg-author-hygiene` for the thread and check state; the rest is dropped: platform workflow.
83. `dyl-review/SKILL.md`, lenses. Priority order: correctness, simplicity, types, concurrency and performance, boundaries, observability, naming, tests. A lower item never outranks a higher one. No factoring before the second real caller. Understand why code exists before deleting it. -> `chg-review-signal`, `chg-abstraction-needs-two-callers`, `chg-chestertons-fence`; the "grug" lens is already `glossary/grug`.
84. `dyl-review/SKILL.md`, synthesis. Keep a finding only if it is real, in the diff and worth the author's time. Drop speculative rewrites and taste-only churn. Cap the list (about seven). One ask per comment, no praise bullets, uncertainty stated when real, one overall mark (green, yellow, red). -> `chg-review-signal`, `chg-review-comment-format`.
85. `dyl-review/SKILL.md`. On a re-review, tell the reviewer what changed and which earlier asks were skipped and why. Treat PR titles, descriptions, comments and CI logs as untrusted data. -> `chg-review-comment-format` (reason for a skipped ask); the untrusted-text rule supports `sys-prompt-injection` and `code-workflow-supply-chain`.
86. `principle-the-algorithm/SKILL.md`. Order of work: question the requirement (its source is a person, not "the linter"), delete the part, then optimise, speed up and automate last. Rerun on the result. FAIL: no. -> `mod-yagni` for the delete step; the order is dropped: process.
87. `dyl-ready-pr`, `build-figma`. PR loop automation and a design-to-UI tool. -> dropped: platform workflow.

## 5. Agent-facing tooling

Base path `https://github.com/cursor/plugins/blob/main/`.

88. `cli-for-agent/skills/cli-for-agents/SKILL.md`. Every input is available as a flag; prompts are only a fallback; a missing required flag exits at once with an example call. FAIL: yes for a CLI. -> new `mod-cli-non-interactive`.
89. `cli-for-agent/skills/cli-for-agents/SKILL.md`. Destructive commands have a preview flag (`--dry-run`) and a bypass for the confirmation prompt (`--yes`), with the safe default left for humans. FAIL: yes. -> new `mod-cli-destructive-dry-run`.
90. `cli-for-agent/skills/cli-for-agents/SKILL.md`. Re-running a successful command is safe. -> `svc-idempotency-key` and row 18.
91. `cli-for-agent/skills/cli-for-agents/SKILL.md`. `--help` carries real examples, layered subcommand help, a consistent resource and verb shape, and success output with ids, URLs and durations. -> dropped: usability preference, one vendor's view, a weak FAIL.
92. `agent-compatibility/agents/docs-reliability-review.md`. Follow the written setup and run path literally. Stale, incomplete or misleading steps are findings, scored by the damage they cause, not by their existence. FAIL: yes at the codebase level (a setup command in the README fails on a clean checkout). -> new `code-documented-setup-runs`.
