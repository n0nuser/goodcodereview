## Why the brand query does not rank

"Good code review" is a plain English phrase, not a coined brand. Pages from Google, Atlassian, GitHub, and many blogs match the phrase and have years of links. On-page work (title, description, headings, schema) cannot overcome that. What moves it:

1. Links from pages that are already trusted: the launch plan in `founder/PLAN.md` (Show HN, dev.to, Reddit), awesome lists, the skills.sh listing, the Claude plugin directory, and the directories in the `directory-submissions` skill. Each should link to `https://goodcodereview.com/` with "Good Code Review" as the anchor.
2. Indexing: a verified Search Console property, a request to index the home page, and the sitemap. Check `site:goodcodereview.com` first.
3. A page that answers a query people type, such as "code review checklist" or "pull request review checklist" (done in the titles of `change`, `function`, and `codebase`), and later a short guide that targets "what makes a good code review" with the cards as evidence.
4. Entity signals: a Wikidata item is possible without a Wikipedia article and is the quickest `sameAs` target; a GitHub org page, and consistent name and description on every profile.

The branded query `"goodcodereview.com"` or `goodcodereview` as one word is easier to win and is the fair measure of indexing.

## Not changed on purpose

- H1s stay short (`Function audit`). The titles carry the long phrase.
- No `img` elements, so no alt-text or lazy-loading work. Fonts are system fonts and CSS is inline, so there is no render-blocking request.
- Core Web Vitals were not measured: `function.html` (278 KB) and `change.html` (204 KB) are the pages to test in PageSpeed Insights after deploy.
