# Company sweep 2: Shopify, Netflix, Cloudflare, Slack, Dropbox, Airbnb, GitHub

I read these on 2026-10-25. Each page was fetched with curl and its text searched. Netflix post pages return a challenge page to curl, so its posts were read from the blog's own feed (https://netflixtechblog.com/feed), which carries the full post bodies. Haiku workers found the candidate posts. Each row below was checked against the page text, and every quote was seen on the page. The rows are paraphrases. Each one gives the URL, org, year, the point, and the card clause it backs.

## Rows that back a Rule clause

1. https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css. GitHub, 2026. Each component moved from CSS-in-JS to CSS Modules behind a feature flag. Existing visual regression tests checked that the snapshots matched before and after. Quote: "Use existing visual regression tests to verify snapshots were identical." Backs `chg-refactor-has-behaviour-pin`, Rule. The flag rollout also backs `prod-kill-switch-fallback` (switch off), but it is not needed there.
2. https://stripe.dev/blog/formatting-an-entire-25-million-line-codebase-overnight-the-rubyfmt-story. Stripe, 2026. Before formatting the whole codebase, the team built a tool that compared parse trees across formatted files. Later, the full suite ran against both parsers until the output was identical. Quote: "We also built a tool to diff ripper trees across formatted files." Backs `chg-refactor-has-behaviour-pin`, Rule.
3. https://airbnb.tech/infrastructure/migrating-airbnbs-jvm-monorepo-to-bazel/. Airbnb, 2025. Gradle tasks could reach the whole file system. One task cleaned `/tmp` while others used it, and CI failed. Bazel's sandbox exposes only declared inputs. Quote: "If a file isn't declared as an input, it simply doesn't exist." Backs `code-build-hermetic`, Rule. Nothing on pinned toolchains.
4. https://slack.engineering/build-better-software-to-build-software-better/. Slack, 2025. A build step can be cached only if it uses just the inputs it is given and gives the same output for them. Bazel's sandbox lets a step touch only declared input files. Quote: "it only uses the inputs it is explicitly given to produce a specific output value." Backs `code-build-hermetic`, Rule. Nothing on pinned toolchains.
5. https://dropbox.tech/infrastructure/how-we-migrated-dropbox-from-nginx-to-envoy. Dropbox, 2020. Lists hermetic and reproducible builds as a benefit of building in the Bazel monorepo. Quote: "incremental, distributed, hermetic, and reproducible builds." Backs `code-build-hermetic`, Rule, weakly: it names the property without arguing for it.
6. https://dropbox.tech/infrastructure/asynchronous-task-scheduling-at-dropbox. Dropbox, 2020. A task can run more than once, and a worker can die at any point mid-task. The retry can land on another host, and the task code must stay correct. Quote: "Worker processes which execute tasks might die at any point during task execution." Backs `fn-rerun-safe-after-crash`, rerun and crash clauses. The same post proposes a retry cap, then a dead-letter queue, then tools to reschedule from it once the bug is fixed. Quote: "create dead letter queues filled with such misbehaving tasks." Backs `svc-dlq`, Rule. This part is a stated proposal, not a shipped feature.
7. https://netflixtechblog.com/timeseries-tiered-storage-journey-kafka-flink-streams-to-native-cassandra-cold-reads-e59d597c9d60. Netflix, 2026. A downloaded component whose size does not match the manifest is deleted and downloaded again. A marker file records finished initialisation for one backup timestamp. When the timestamp changes, the marker is removed and the work restarts. Quote: "A .timestamp file marks completed initialization and ties it to the backup timestamp." Backs `fn-rerun-safe-after-crash`: crash, derive from current state, and leftovers recognisable as stale.
8. https://netflixtechblog.com/behind-the-scenes-evolving-netflixs-ads-event-pipeline-for-live-part-ii-826ebf9ad9fb. Netflix, 2026. Events arrive at least once, so a stable hash of each event drops repeats. Failed events go to dead-letter queues, and an offline job replays them. Quotes: "The solution here is a simple and idempotent key." and "it can replay dead-letter queues and backfill historical data." Backs `fn-rerun-safe-after-crash`, rerun clause only (same org as row 7), and `svc-dlq`, Rule.
9. https://github.blog/engineering/platform-security/staying-evergreen-how-we-automated-secure-access-and-repo-hygiene-in-a-shared-org. GitHub, 2026. When a removal fails, the access review stays pending, and the next run retries the removals that are left. The review is marked revoked only once every removal has succeeded. Quote: "It only records "revoked" once every removal actually succeeded." Backs `fn-rerun-safe-after-crash`: rerun, derive from current state, and leftovers recognisable (half-done work stays visibly pending).
10. https://blog.cloudflare.com/18-november-2025-outage/. Cloudflare, 2025. After the outage, remediation includes more global kill switches for features. Quote: "Enabling more global kill switches for features." Backs `prod-kill-switch-fallback`, switch-off clause. It is a stated plan.
11. https://blog.cloudflare.com/5-december-2025-outage/. Cloudflare, 2025. A kill switch, delivered through global configuration, disables a misbehaving rule quickly. It had been used in past incidents and had a written procedure. Applied to a rule type it had never been used on, it raised an error. Quote: "we have never before applied a killswitch to a rule with an action." Backs `prod-kill-switch-fallback`, both clauses, and `inc-rollback-path-tested`, Rule.
12. https://blog.cloudflare.com/cloudflare-incident-on-november-14-2024-resulting-in-lost-logs/. Cloudflare, 2024. The system was designed to fail open, but nobody regularly tested that the systems behind it could take a fail-open event. Cloudflare already runs regular cut tests and plans regular overload tests. Quote: "we neglected to regularly test that the broader system." Backs `prod-kill-switch-fallback`, exercise clause, and `inc-rollback-path-tested`, Rule.
13. https://github.blog/engineering/engineering-principles/how-we-improved-availability-through-iterative-simplification. GitHub, 2024. Changes roll out through Flipper to early-access users, then to a growing share, and must be possible to roll back. Quote: "We also need to be able to roll back in the event of unexpected behavior." Backs `prod-kill-switch-fallback`, switch-off clause.
14. https://slack.engineering/slack-ai-the-path-to-multi-cloud/. Slack, 2026. Traffic moved gradually behind feature flags, with instant rollback. Quote: "gradual traffic shifts via feature flags and instant rollback capabilities." Backs `prod-kill-switch-fallback`, switch-off clause.
15. https://dropbox.tech/infrastructure/lessons-learned-in-incident-management. Dropbox, 2021. Core teams could not roll back experiment and feature-gate changes in an emergency. The experimentation team gave every gate an owner and gave on-call rollback tools and a playbook. Quote: "ensured all experiments and feature gates had a clear owner." Backs `prod-kill-switch-fallback`, switch-off clause, and the owner clause of `chg-flag-owner-retirement` (one org there).
16. https://shopify.engineering/four-steps-creating-effective-game-day-tests. Shopify, 2019. Game Days trigger failure modes in production on purpose and check that systems behave as expected. They are repeated with new hypotheses. Quote: "a Game Day test isn't a one-time event." Backs `prod-kill-switch-fallback`, exercise clause, and `inc-rollback-path-tested`, Rule.
17. https://aws.amazon.com/builders-library/caching-challenges-and-strategies/ (redirects to builder.aws.com), re-checked. AWS. The team tests the service with caching disabled to check that the safeguards work. Quote: "We test service behavior with caching disabled." Backs `prod-kill-switch-fallback`, exercise clause. It names no schedule.
18. https://dropbox.tech/infrastructure/disaster-readiness-test-failover-blackhole-sjc. Dropbox, 2022. Dropbox ran failovers quarterly from 2019, then monthly once a dedicated team owned them. Runbook tasks became reusable, so each can be tested on its own more often. Quote: "we could run failovers monthly instead of quarterly." Backs `inc-rollback-path-tested`, Rule.
19. https://slack.engineering/break-stuff-on-purpose/. Slack, 2024. A restore failed because the newest backup was almost two years old and the runbook was out of date. The team then broke a development cluster on purpose to test the fixed runbook. Quote: "Unless you actively exercise your processes, procedures, and runbooks." Backs `inc-rollback-path-tested`, Rule.
20. https://slack.engineering/deploy-safety/. Slack, 2025. Rollback tooling must be used often, so that teams are fluent with it before an incident. Quote: "Use the tooling often, not just for the infrequent worst case scenarios." Backs `inc-rollback-path-tested`, Rule. Same org as row 19.
21. https://aws.amazon.com/builders-library/avoiding-insurmountable-queue-backlogs/ (redirects to builder.aws.com), re-checked. AWS. A message that runs out of retries goes to a dead-letter queue. The team alarms on any message there and re-processes the messages after the fix. Quote: "The benefit of the DLQ is that it lets us re-process the messages." Backs `svc-dlq`, Rule. The alarm backs the Why.
22. https://netflixtechblog.com/netflix-conductor-the-next-chapter-41ad21067649. Netflix, 2026. Concurrent updates to one workflow raced for a lock. Updates now go to an exclusive queue, and one evaluator works on each workflow at a time. Quote: "only one worker ever evaluates a given workflow at a time." Backs `mod-single-writer-per-state`, Rule.
23. https://tech.cabify.com/blog/engineering/scaling-argocd-to-dozens-testing-environments. Cabify, 2025. Deploys ran from CI pipelines that were not mutually exclusive, so a later run could revert an earlier one. The team moved to a GitOps model with an ArgoCD instance per testing cluster. Quote: "CI executions were not mutually exclusive, leading to concurrency issues." Backs `mod-single-writer-per-state`, Rule.
24. https://github.blog/engineering/architecture-optimization/the-bridge-to-agent-scale-git-infrastructure. GitHub, 2026. Writes now queue per reference instead of per repository. Writes to different branches proceed at the same time, and only writes to the same reference wait. Quote: "only writes that contend on a shared reference must wait for each other." Backs `mod-single-writer-per-state`, Rule (serialise writes to one piece of state), and the split-state sentence in its Why.
25. https://google.github.io/eng-practices/review/reviewer/standard.html, re-checked. Google. Prefix a comment that is only polish with "Nit:", so the author knows it can be ignored. Quote: "prefix it with something like "Nit: "." Backs `chg-review-comment-format`, Rule.
26. https://blog.pragmaticengineer.com/good-code-reviews-better-code-reviews/, re-checked. Gergely Orosz. Good reviews make clear which comments are non-blocking. Quote: "they make it clear which questions or comments are non-blocking or unimportant." Backs `chg-review-comment-format`, Rule.
27. https://blog.cloudflare.com/ai-code-review/. Cloudflare, 2026. Each AI review finding carries a severity: critical, warning, or suggestion. Quote: "Every reviewer produces findings in a structured XML format with a severity classification." Backs `chg-review-comment-format`, Rule. Each sub-reviewer runs in its own session, which bears on the fresh-context option of `chg-agent-independent-review`. The merge requests it reviews are written by engineers, though, so that card does not count it.
28. https://dropbox.tech/security/dropbox-mcp-dash-design-code-security. Dropbox, 2026. Most review findings should be advisory, and blocking is kept for confirmed gaps between design and code. Quote: "Most findings should be advisory rather than blocking." Backs `chg-review-comment-format`, Rule. Its comparison of code against documented security decisions bears on `chg-matches-spec`, but only for security designs.
29. https://dropbox.tech/culture/beyond-code-generation-rethinking-engineering-productivity-in-the-age-of-ai-agents. Dropbox, 2026. Agent-written work is validated, and a person makes the final judgment before any code reaches production. Quote: "have a human make the final judgment before any code reaches production." Backs `chg-agent-independent-review`, the person half of the Rule.
30. https://tech.cabify.com/blog/engineering/cabify-container-certification. Cabify, 2025. Images are scanned for CVEs with Trivy at build, and a Trivy operator rescans running images every 6 hours. Quote: "Trivy operator scans running images with CVE database updates every 6 hours." Backs `code-dependency-licence-sbom`, scan clause (a fourth org).

## Checked, not added

- `chg-delete-legacy-after-migration`. Dropbox (https://dropbox.tech/infrastructure/courier-dropbox-migration-to-grpc): "migration is only finished after cleanup is performed", with cleanup as a later step. GitHub (row 1) removed the old styling libraries after the migration. Netflix (https://netflixtechblog.com/beyond-api-compatibility-building-a-tool-to-measure-the-blast-radius-of-library-changes-9474f2fd4f90) checks callers before it removes a method. Shopify (https://shopify.engineering/refactoring-legacy-code-strangler-fig-pattern) deletes the strangled code as a later step. Slack (https://slack.engineering/hakana-taking-hack-seriously/) bulk-deletes unused functions after migrations. They back deleting the old path, but not doing it in the same change.
- `chg-flag-owner-retirement`. Shopify (https://shopify.engineering/using-betas-to-deploy-new-features-safely): beta flags outlive their teams and leave dead code. That backs the Why only.
- `chg-matches-spec`. Shopify (https://shopify.engineering/great-code-reviews): a poorly defined goal comes before the code. That is not tracing a diff to a requirement.
- `chg-rollback-path`. Airbnb (https://airbnb.tech/infrastructure/seamless-istio-upgrades-at-scale/), Netflix (row 8, the old job keeps running until the new one is healthy), Stripe's document-database post at its real slug (https://stripe.dev/blog/how-stripes-document-databases-supported-99.999-uptime-with-zero-downtime-data-migrations; bidirectional replication so traffic can revert), Stripe Radar, and the Uber posts all describe a rollback ability. None says to state the undo in the change description.
- `code-a11y-check-in-ci`. Dropbox (https://dropbox.tech/frontend/creating-a-culture-of-accessibility): automated checks can go into linters and unit tests. Slack (https://slack.engineering/automated-accessibility-testing-at-slack/): axe runs inside Playwright tests, but the suite is non-blocking, and a blocking suite is planned. GitHub (https://github.blog/engineering/user-experience/your-alt-text-passes-automated-checks-that-doesnt-mean-its-any-good): treats its findings as prompts. None backs failing on a violation.
- `code-scoped-validation-loop`. Dropbox (https://dropbox.tech/infrastructure/continuous-integration-and-deployment-with-bazel, https://dropbox.tech/mobile/revamping-the-android-testing-pipeline-at-dropbox): CI runs only the affected tests. Neither is a documented local command.
- `inc-perf-regression-guard`. Airbnb (https://airbnb.tech/infrastructure/load-testing-with-impulse-at-airbnb/), Dropbox Apogee (https://dropbox.tech/infrastructure/keeping-sync-fast-with-automated-performance-regression-detectio), GitHub (https://github.blog/engineering/user-experience/rendering-huge-pull-requests-in-the-github-copilot-app) and Netflix (https://netflixtechblog.com/single-tenant-titus-vm-level-isolation-on-a-multi-tenant-container-platform-6d8b1909d163) run performance checks in CI or on a schedule. None makes the check a postmortem action. Dropbox row 15's push-time fix came from a risk assessment, not a postmortem.
- `inc-postmortem-owned-actions`. Dropbox (courier post) and Shopify (https://shopify.engineering/implementing-chatops-into-our-incident-management-procedure) mention postmortem action items, but name no owner or due date.
- `mod-cohesive-unit`. Shopify (strangler-fig post: a 3,000-line `Shop` class split into components) and Cabify (https://tech.cabify.com/blog/engineering/what-to-do-when-your-code-is-starting-to-smell: search logic moved out of models) back the Rule. That makes 2 firm orgs, because the dev.to Ousterhout summary is secondary.
- `mod-mock-at-boundaries-only`. Airbnb (Impulse post) mocks downstream services in load tests. Cabify (https://tech.cabify.com/blog/engineering/from-polling-to-grpc-streaming) runs a real in-process gRPC server in tests instead of a mock. Neither states the Rule.
- `mod-one-name-per-concept`. Netflix (https://netflixtechblog.com/ontology-driven-observability-building-an-end-to-end-knowledge-graph-at-netflix-scale-421392cf5adf) refused a generic "Service" type, because the word meant four things. Slack (https://slack.engineering/its-a-non-transitive-r-class-world/) made import aliases consistent. Netflix backs the converse (one concept per name), and Slack is narrow.
- `mod-proto-enum-zero-unspecified`. Dropbox (courier post) uses `UNKNOWN = 0`, a zero with no real meaning, but does not name it `_UNSPECIFIED`. Cabify (gRPC post) lints for "consistent enum zero values" without naming the convention.
- `mod-validate-at-boundary-once`. Cloudflare (row 10, generated config hardened like user input), Netflix (ontology post, every application validated against the catalog), Shopify (https://shopify.engineering/managing-pii-shopify-scale, a schema enforced on every event) and Uber (https://www.uber.com/blog/scaling-verify-wallet/, every response validated) back validating at the boundary. None backs "once", and only Shopify uses a schema.
- `prod-slo-error-budget`. Cloudflare (https://blog.cloudflare.com/cloudflare-incident-on-august-21-2025/) defines latency SLOs, and Slack (https://slack.engineering/service-delivery-index-a-driver-for-reliability/) sets goals on a composite metric. Neither uses an error budget to gate releases.
- `py-test-hygiene`. Shopify (https://shopify.engineering/spark-joy-by-running-fewer-tests) lists time, HTTP connections and leaked state as causes of flaky tests. That is Why material.
- `svc-api-safe-idempotent-methods`. Dropbox (https://dropbox.tech/developers/limitations-of-the-get-method-in-http): "HTTP GET requests should not modify server state". That backs the GET clause, which stable `svc-csrf-state-changing` already covers. Shopify (https://shopify.engineering/building-resilient-graphql-apis-using-idempotency) puts idempotency keys on mutations, not PUT or DELETE.
- `svc-api-spec-matches-impl`. Cloudflare (https://blog.cloudflare.com/keeping-cloudflare-api-all-green-using-python-based-testing/) names it a gap that its old tests did not fail on a schema mismatch. That makes 2 orgs for the test clause, with Stripe.
- `svc-circuit-breaker-bulkhead`. Shopify (https://shopify.engineering/circuit-breaker-misconfigured) gives each service type its own named circuit breaker, which is a breaker, not a concurrency limit. GitHub (https://github.blog/engineering/architecture-optimization/from-latency-to-instant-modernizing-github-issues-navigation-performance) uses low-priority workers. Netflix (row 7) uses a dedicated pool for initialisation. Neither isolates by downstream dependency.
- `prod-kill-switch-fallback`, not needed. Airbnb's Mussel (https://airbnb.tech/infrastructure/building-a-next-generation-key-value-store-at-airbnb/), Bazel (row 3) and Sitar (https://airbnb.tech/infrastructure/sitar-agent-building-a-reliable-dynamic-configuration-sidecar-at-scale/) posts, Slack notifications (https://slack.engineering/how-slack-rebuilt-notifications/), and Netflix row 8 ("the metadata registry had no fallback") back the Why.
