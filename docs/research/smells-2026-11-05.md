# Code smells as cards: sources for Repeated Switches and Shotgun Surgery

Fetched 2026-11-05 through WebFetch; quotes are verbatim.

1. https://refactoring.guru/smells/switch-statements (org: Refactoring.Guru). "When a new condition is added, you have to find all the switch code and modify it." Treatment: "use Replace Conditional with Polymorphism". When to ignore: "When a switch operator performs simple actions, there's no reason to make code changes." Backs `mod-no-repeated-switches`.
2. https://shopify.engineering/other-driven-developments (org: Shopify). Replaces an `or`/`elsif` branch with a polymorphic `persist` on the item (read in `size-branches-types-orgs-F.md`). Backs `mod-no-repeated-switches`.
3. https://refactoring.guru/smells/shotgun-surgery (org: Refactoring.Guru). "Making any modifications requires that you make many small changes to many different classes." Cause: "A single responsibility has been split up among a large number of classes." Treatment: Move Method and Move Field into one class, then Inline Class. No "when to ignore" section. Backs `mod-no-shotgun-surgery`.
4. https://dev.to/sportebois/software-design-red-flags-wisdom-nuggets-from-john-ousterhout-43i2 (person: Ousterhout, summarised). Information leakage: the same decision encoded in several modules. Reference only. Backs `mod-no-shotgun-surgery`.

Count: Repeated Switches 2 organisations (Refactoring.Guru, Shopify); Shotgun Surgery 1 (Refactoring.Guru) plus a person. Both stay `draft`. A third organisation for each needs another pass (Google, Microsoft, Linux kernel, Go and JetBrains inspections are the places to look).
