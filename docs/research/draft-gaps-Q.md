## Rows

1. https://testing.googleblog.com/2008/08/by-miko-hevery-so-you-decided-to.html (org: Google). Google's Testing Blog, "Writing Testable Code". It states the replacement as a practice: "Favor polymorphism over conditionals: If you see a switch statement you should think polymorphisms. If you see the same if condition repeated in many places in your class you should again think polymorphism." The reason is the same one the card gives: "Polymorphism will break your complex class into several smaller simpler classes which clearly define which pieces of the code are related and execute together." Backs **mod-no-repeated-switches**, the "repeated condition → polymorphism" half. Not the "one lookup table" alternative, and the post says "in your class", not "in the module". The post is by Miško Hevery but it is published on Google's own blog, so it counts as Google.

2. https://about.gitlab.com/blog/gitlab-top-devops-tooling-metrics-and-targets/ (org: GitLab). A team page describing GitLab's measured target for a whole run: "When a pipeline is started for a merge request, how long does it take to run?" and "Our target for this metric is below 45 minutes." It also says the team breaks the duration into stages and "iterates and improves time efficiencies of each stage of the pipeline." Backs **code-test-suite-time-budget**, the "written budget for the whole run, not one test" half. It does **not** say the pipeline fails or is cut at 45 minutes; it is a monitoring target. The URL is not covered by `tools/orgs.py` today (see Notes).

3. https://docs.skypilot.ai/en/v0.10.0/developers/CONTRIBUTING.html (org: the SkyPilot project, `skypilot-org`). Its contributing guide makes import time something to measure and act on: "Use `LazyImport` for third-party modules that meet these criteria: The module is imported during `import sky`; The module has a significant import time (e.g. > 100ms)" and then "To measure import time: Basic check: `python -X importtime -c "import sky"`; Detailed visualization: use `tuna`". Backs **py-test-collection-and-imports**, the `-X importtime` clause. Caveat: the page is about `import sky` start-up, not a pytest run or test collection. `docs.skypilot.ai` is not in `tools/orgs.py`.

4. https://rust-lang.github.io/api-guidelines/type-safety.html (org: the Rust project). The Rust API Guidelines, "Type safety", C-CUSTOM-TYPE: "Use a deliberate type (whether enum, struct, or tuple) to convey interpretation and invariants." And the reason the card needs: "Using custom types makes it easier to expand the options later on, for example by adding an `ExtraLarge` variant." Backs **fn-no-stringly-typed-returns**, the "use a tagged type rather than a primitive" half. Caveat: the guideline is titled "Arguments convey meaning through types, not `bool` or `Option`"; its example is a function argument, not a return value.

5. https://kotlinlang.org/docs/sealed-classes.html (org: JetBrains). Kotlin's sealed-classes guide puts a closed error hierarchy in the return position: "with a sealed hierarchy of error classes, library authors can be sure that they know all the possible error types and that other error types can't appear later", and "The `when` expression, used with a sealed class, allows the Kotlin compiler to check exhaustively that all possible cases are covered." The page's own API example returns the sealed type: `fun handleRequest(request: ApiRequest): ApiResponse`. Backs **fn-no-stringly-typed-returns**, the "return a tagged type whose cases the caller must handle" half. It does not say "instead of a string"; the case it discusses is an error hierarchy.

6. https://developer.apple.com/videos/play/wwdc2020/10680/ (org: Apple). WWDC20 "Refine Objective-C frameworks for Swift", transcript. It names the stringly-typed problem and the replacement: "what Swift sees is this function takes a string. These constants are all strings, but there are a heck of a lot more strings out there too", and "You'd just turn these constants into an enum or a struct with a raw value of type String, and then change the function to take only that type." Backs **fn-no-stringly-typed-returns**, the "enum instead of a bare string for a closed set" half. Caveat: the quoted function is an argument, not a return value.

7. https://learn.microsoft.com/en-us/dotnet/standard/design-guidelines/enum (org: Microsoft). The Framework Design Guidelines state the return position explicitly: "✔️ DO use an enum to strongly type parameters, properties, and return values that represent sets of values." It also names the card's limit: "❌ DO NOT use an enum for open sets (such as the operating system version, names of your friends, etc.)." Backs **fn-no-stringly-typed-returns**, the "return value of a closed set is an enum" clause. Strong on that clause, but it is the only source found that says "return values".

8. https://raw.githubusercontent.com/SonarSource/sonar-dotnet/master/analyzers/rspec/cs/S1450.html (org: SonarSource). Rule S1450, title from its metadata: "Private fields only used as local variables in methods should become local variables." The rule text: "When the value of a private field is always assigned to in a class' methods before being read, then it is not being used to store class information. Therefore, it should become a local variable in the relevant methods to prevent any misunderstanding." Its noncompliant example is a field assigned and read only inside `DoSomething`. Backs **K2 Temporary Field**, the prose statement and the fix. This is the clean prose statement the task asked for. Caveat: the condition is "always assigned before read in every method", not literally "used by one method".

9. https://docs.pmd-code.org/latest/pmd_rules_java_design.html (org: PMD). Rule `SingularField`: "Reports fields which may be converted to a local variable. This is so because in every method where the field is used, it is assigned before it is first read. Hence, the value that the field had before the method call may not be observed, so it might as well not be stored in the enclosing object." Backs **K2 Temporary Field**, the mechanism as a tool gate. PMD also documents the false-positive limit: "The rule is not aware of threading, so it may cause false positives in concurrent code." Its wording is assignment-before-read, not "one method", so it is a weaker statement of K2 than Sonar's.

10. https://peps.python.org/pep-0589/ (org: Python Software Foundation). PEP 589, a Final Standards Track PEP, gives the fixed-key dictionary a type and says why the generic dict is not enough: "The PEP 484 type `Dict[str, Any]` would be suitable, but it is too lenient, as arbitrary string keys can be used, and arbitrary values are valid." And: "A TypedDict type represents dictionary objects with a specific set of string keys, and with specific value types for each valid key." Backs **fn-known-keys-get-a-type**, both the "fixed keys get a type" clause and the "generic map only for open keys" clause. A published standard states a practice, so it counts under rule 3.

11. https://www.attrs.org/en/stable/why.html (org: the attrs project, `python-attrs`). The project's own "Why not…" page is blunt: "Dictionaries are not for fixed fields." and "In other words: if your dict has a fixed and known set of keys, it is an object, not a hash. So if you never iterate over the keys of a dict, you should use a proper class." It also says the class is what lets you say "whether you take a parameter of that class or return a value of that class." Backs **fn-known-keys-get-a-type**, both the fixed-key clause and the record-type fix. Caveat: this is project documentation, not a company; `attrs.org` is not in `tools/orgs.py`.

12. https://learn.microsoft.com/en-us/previous-versions/msp-n-p/ff649585(v=pandp.10) (org: Microsoft). The old patterns & practices "Data Transfer Object" page contrasts a keyed collection with a typed object: "Creating custom classes for each DTO provides strongly-typed objects that the client application can access exactly like any other object, so they provide compile-time checking", while "collections store items of the same type (usually the most generic Object type), which can lead to subtle but fatal coding errors that cannot be detected at compile time." Backs **fn-known-keys-get-a-type**, the fixed-key record clause. The page carries "Retired Content … outdated and is no longer being maintained", so it is a supporting source, not one of the three counted below.

## Counter-evidence

- **mod-no-repeated-switches** — https://kotlinlang.org/docs/sealed-classes.html (JetBrains) recommends one sealed hierarchy and one exhaustive `when`; read strictly, that keeps a switch and only centralises it, which is compatible with the card but not the same as "replace every copy with a polymorphic method". Google's blog post is from 2008, is about testability, and says "in your class"; it is not a current style rule and does not mention a lookup table. The card's "or one lookup table" alternative still has no dedicated source.
- **code-test-suite-time-budget** — GitLab's 45 minutes is an **MR pipeline duration target**, not a test-suite total and not a build-failing gate. Etsy's "Divide and Concur" (UNFETCHED, see below) is the closest whole-suite cap found — about 11 minutes for 7,000 trunk tests, chosen so the suite can be re-run once inside a 20-minute deploy window — but it is a deployment design, not a test that fails the build. The card's "fail the build" clause therefore still has thoughtbot and Shopify only (2 orgs), even if GitLab is accepted for the "written total budget" clause.
- **py-test-collection-and-imports** — SkyPilot uses `-X importtime` on `import sky`, not on `pytest`; it sets no collection budget and does not mention `--collect-only` or `testpaths`. The third source for the import-profiling clause is real, but it is one step away from the card's pytest context.
- **fn-no-stringly-typed-returns** — Microsoft's own page says "❌ DO NOT use an enum for open sets", so "never a bare string" cannot be a universal rule; wire formats and open sets need strings. Apple's advice is about a function **parameter**, Kotlin's about an **error return hierarchy**, and Rust's about **arguments**. Only Microsoft states "return values". The Rule may need to widen from "Return an enum" to "Use a named closed type in the API" before these three partial sources can carry rule 1.
- **fn-known-keys-get-a-type** — PEP 589 itself says TypedDict is for dictionary-shaped data and notes that "dataclasses don't directly support JSON serialization", so a wire/JSON dict is not automatically a violation. It also only covers the "fixed keys" case; open-key maps are explicitly fine. The attrs page is project docs, and the Microsoft DTO page is retired content, so the three counted orgs are mypy, PSF, and attrs.
- **K2 Temporary Field** — Sonar S1450 is "always assigned before read in every method", not "used by one method"; a field can be assigned in one method and read in another and still be flagged. PMD's `SingularField` has the same wording and warns of threading false positives. Serialization/ORM models (pydantic, EF, Lombok) are the known false-positive class, which is why the candidate Rule's `N/A` scope matters.

## Notes for the parent

- `tools/orgs.py` has no prefix for `about.gitlab.com` (GitLab), `docs.skypilot.ai` (SkyPilot), `attrs.org` (attrs project), or `raw.githubusercontent.com/SonarSource/` (SonarSource). Rows 2, 3, 8, and 11 need mappings before `python3 tools/validate.py` will accept them on a card. `developer.apple.com` is already mapped to `apple`; `kotlinlang.org` to `jetbrains`; `rust-lang.github.io` to `rust`; `peps.python.org` to `psf`; `docs.pmd-code.org` to `pmd`; `testing.googleblog.com` to `google`; `learn.microsoft.com` to `microsoft`.
- `mod-no-repeated-switches`: Google is the clean third organisation the card asked for. The card's `lacks:` line can drop to a narrower note only if the "or one lookup table" clause is not counted separately. Keep Reek out unless the project-owner question is decided.
- `code-test-suite-time-budget`: GitLab gives the third org for "a written budget for the whole run", but the `lacks:` line's "fails or cuts a CI run" is still two orgs. The Etsy page is worth one browser fetch before rewriting the Rule; its 11-minute cap is the closest thing to the card's intent.
- `py-test-collection-and-imports`: SkyPilot closes the `-X importtime` gap, but the card should say "measure import time" rather than "measure a pytest run" if SkyPilot is to carry that clause.
- `fn-no-stringly-typed-returns`: this is the one card the pass could not make clean. Microsoft is exact; Apple, Kotlin/JetBrains and Rust all state the principle but in the argument or error-return position. Either widen the Rule to "Use a named closed type in the API" (then three of the four support it) or find one more source that says "return values" in so many words.
- `fn-known-keys-get-a-type`: PEP 589 and attrs give the two missing organisations. The Microsoft DTO page is a useful fourth but is archived, so do not count it unless the parent decides retired Microsoft guidance still counts.
- K2 has no card file; the candidate Rule is in `docs/research/smells-K.md`. SonarSource S1450 is the prose source the task asked for; PMD `SingularField` is the tool gate, with the threading caveat.
